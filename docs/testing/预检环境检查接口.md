# 无额外配置的预检与测试报告

DBChaos 使用已有数据库连接配置及故障命令参数运行，不需要设置 `DBCHAOS_PREFLIGHT_*` 环境变量，也不需要填写服务器数据目录、日志目录或预估数据/日志增长速率。

## 自动预检

第 11～21 行用例的入口及 SQL 检查清单见 [故障注入测试参数手册](故障注入测试参数手册.md)。预检复用注入器的 JDBC 连接，检查参数、权限相关能力、数据库配置、目标表及小规模 SQL 能力；不再调用外部服务器、内存或业务监控检查程序。现有 JVM 堆和 Java 数组大小检查继续自动执行。

必要的 SQL 条件不满足或能力探测失败时，正式注入不会开始，CLI 输出失败报告并以状态码 1 退出。帮助命令不执行预检或生成测试报告。

服务器磁盘容量、物理/容器内存及业务是否访问目标热点不作为额外配置门槛，也不被宣称已经验证。运行期间的资源不足和连接中断作为实验现象记录；故障是否生效及数据库韧性仍需结合注入器计数、业务影响和恢复情况判断。

## 报告接口

基类 `BaseFaultInject` 定义 `public abstract void reportTest()`。现有注入器实现该方法并调用 `printTestReport()`；子类可补充自己的效果指标。新用例模板包含此接口。

CLI 通过 `executeWithReport(String[] args)` 执行注入器，在正常结束或异常退出前统一调用 `reportTest()`。程序化调用者也应使用此入口；直接调用 `execute()` 不会自动生成通用报告。原有用例效果指标继续输出。

工作线程和清理逻辑捕获异常后使用 `recordTestError(Throwable)` 记录，报告包含：

- 故障类型、数据库类型、执行状态及耗时。
- 异常记录数和最多五个异常样本，包括可获得的 SQLState；该数量不是失败 SQL 的精确计数。
- 根据异常提供的环境检查建议：数据/日志盘及配额、数据库/执行机内存及 JVM 堆、账号权限、连接限额、网络和数据库功能支持等。

检查建议用于辅助排查，不自动认定异常由环境配置导致。重复键冲突、死锁、资源耗尽等也可能是目标故障行为。已捕获的异常标记为“执行结束，存在错误记录”；向入口传播的异常标记为“执行失败”，并保留非零退出码。无有效注入的已有退出码 3 保持不变。

报告输出到标准输出，可随命令日志保存；不需要配置报告路径。使用 `--wait-stable` 时，另自动保存全程业务 TPS、数据库探针和六项韧性指标，并在 `reportTest()` 中输出性能下降、持续服务和恢复分析，见[业务韧性指标与全程报告](韧性指标与报告.md)。通用报告屏蔽当前连接 URL 和密码。进程被强制杀死、JVM 崩溃或严重内存耗尽时，无法保证报告完整输出。

仓库保留的 `PreflightEnvironment` 和 `scripts/probe/check_fault_prerequisites.py` 是旧的独立检查工具，不在故障注入路径中调用。

## 回归验证

```bash
python3 -m unittest discover -s tests -p test_preflight.py
```

回归测试使用模拟 JDBC，不连接真实数据库、不执行压力负载。覆盖无外部检查配置的 SQL 预检、异常报告、线程异常汇总、环境建议、预期 SQL 冲突、报告状态重置、凭据屏蔽及 CLI 非零退出。
